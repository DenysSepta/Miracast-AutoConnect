The sequence

From TV to desktop.

The TV starts the request; a small Windows-side listener handles the trigger and asks the operating system to begin projection. The goal is to remove the manual UI step—not to bypass Miracast compatibility or pairing requirements.

01 / RECEIVER

Put the TV in waiting mode

Open the TV's Miracast receiver so it is ready to accept a wireless display connection.

02 / TRIGGER

Send the signal

Launch the Android TV app or use a configured remote-button trigger to send a message on the local network.

03 / WINDOWS

Request projection

The PowerShell listener receives the UDP packet and requests projection through Windows Runtime APIs.

04 / VERIFY

Confirm the picture

Check that the Windows desktop is visible on the TV. A received packet or API response alone is not proof of a live session.

Implementation notes

Built around the real connection path.

This project focuses on initiating projection from a background process rather than scripting the Windows projection flyout.

Windows side
PowerShell listener + Windows Runtime ProjectionManager
Trigger
Local UDP message, default port 8888
TV side
Android TV app and compatible Miracast receiver mode
Requirements
Compatible Wi-Fi adapter, driver, Windows wireless projection support, and TV firmware
Limitations
Device discovery, receiver state, drivers, and network conditions can affect connection success
Maintainer's test setup

End-to-end desktop mirroring has been verified by the maintainer on a Xiaomi TV A 65 (2025) with Windows 11 Home build 26300 and a Realtek RTL8852BE Wi-Fi adapter. The configured background workflow continued working after reboot. Results may differ on other hardware and firmware.
